Como eu testo

O mesmo caminho do laboratório acima, em quatro passos.

  1. Começo pelo risco

    O que custa dinheiro ou irrita o cliente vem primeiro. No portfólio, listei 10 riscos e dei nota de probabilidade e impacto a cada um.

  2. Transformo em cenários

    Escrevo em Gherkin, com os casos de borda que costumam esconder bugs, como o frete em exatamente R$ 200,00.

  3. Confiro em três camadas

    A tela com Cypress, a API com Postman e o banco de dados com SQL. Um reembolso só está certo quando os três concordam.

  4. Deixo rodando sozinho

    A cada alteração no código, o GitHub Actions roda tudo e avisa se algo quebrou.
